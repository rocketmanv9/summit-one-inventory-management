# Summit One Inventory Management

## What this is
Summit One Inventory Management is a Next.js microservice in the Summit One ecosystem. It handles multi-tenant inventory, procurement, assets, and related workflows backed by Supabase (Postgres + RLS).

## Tech stack
- Next.js 15 (App Router)
- TypeScript
- Supabase (Postgres + RLS)
- Tailwind CSS + shadcn/ui
- `@rocketmanv9/chassis` (route factories, auth, events, idempotency)

## Getting started

### Prereqs
- Node.js 20+
- GitHub PAT with `read:packages` for `@rocketmanv9` packages

### Environment variables

Copy [.env.example](.env.example) to `.env.local` and fill in values.

#### REQUIRED (App will not function without these):

| Variable | Description |
|----------|-------------|
| `NEXT_PUBLIC_SUPABASE_URL` | Supabase project URL (use the shared dev project, not local) |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Supabase anon public key |
| `SUPABASE_SERVICE_ROLE_KEY` | Supabase service role key (server-side only) |
| `SUPABASE_JWT_SECRET` | Supabase JWT secret for signing/verifying JWTs |
| `CORE_EXCHANGE_URL` | Summit Core SSO exchange endpoint |
| `CORE_ANON_KEY` | Core SSO anon key (used by chassis for ticket exchange) |
| `NEXT_PUBLIC_CORE_APP_URL` | Summit Core app URL (for login redirects) |
| `INTERNAL_JWT_SECRET` | Chassis internal JWT secret (generated by `chassis init`) |
| `GV_SUPABASE_URL` | Global Values Supabase project URL |
| `GV_SUPABASE_ANON_KEY` | Global Values Supabase anon key |

#### OPTIONAL (Recommended for production):

| Variable | Description |
|----------|-------------|
| `OPENAI_API_KEY` | AI chat features (falls back to keyword mode without it) |
| `SENTRY_DSN` | Error tracking |
| `UPSTASH_REDIS_REST_URL` | Rate limiting (with `UPSTASH_REDIS_REST_TOKEN`) |
| `WEBHOOK_SECRET` | Webhook signature verification |
| `EVENTS_WEBHOOK_URL` | Event consumer endpoint |
| `DATABASE_URL` | Direct DB connection (migrations, scripts only) |

See [.env.example](.env.example) for full list and descriptions.

### Run locally
1. Install dependencies: `npm install`
2. Copy `.env.example` to `.env.local` and point at the shared dev Supabase project
3. Run the app: `npm run dev`
4. Open `http://localhost:3000`

**Note:** Normal development runs against the shared dev Supabase project (no local database). See [docs/development.md](docs/development.md) for details.

## Auth
This service uses Summit One Core ticket-based SSO and mints Supabase-compatible JWTs. Auth is enforced at the route level by chassis route factories (`createSessionReadRoute`, `createSessionWriteRoute`), not by middleware. See [docs/AUTH.md](docs/AUTH.md) for the full flow.

## Deployment

This service deploys on Vercel with branch-based environments:

- **dev** (default branch) - Development
- **stage** - Staging / QA
- **prod** - Production

CI applies Supabase migrations before deploying. See [docs/VERCEL_DEPLOYMENT.md](docs/VERCEL_DEPLOYMENT.md) and [docs/development.md](docs/development.md) for workflow details.
